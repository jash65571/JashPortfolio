01 / CONTEXT

A production order is more than a row in a database. It has artwork, work orders, packaging rules, shipping details, and people waiting for the next step.

EPOD had a legacy PHP/jQuery codebase with tightly connected order and workflow logic. Changing one part of the flow could make production issues hard to isolate. Internal users also needed a faster, clearer interface.

02 / ENGINEERING DECISIONS
01

Modernize around the work.

My work moves EPOD toward PHP/Laravel services and a React frontend. I refactor order, signage, and work-order logic into REST APIs so interface changes and business rules are easier to reason about on their own.

02

Get the operational details right.

I implement FedEx shipping, dynamic packaging, and billing validation. These are the places where a small software error becomes a manual correction for someone else. My focus is on catching those mistakes within the workflow.

03

Own the release, too.

I build Docker images and Jenkins deployment pipelines for applications running on AWS. When an issue reaches production, I trace it across the interface, backend, database, and deployment logs, then validate the fix before release.

04

A connected family of applications.

Alongside EPOD, I build and maintain FotoPrint, ABC2, DryInk, and related tools for photo, signage, packaging, and order processing. I also review PHP and Java changes and help teammates debug production issues.
