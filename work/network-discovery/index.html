01 / CONTEXT

A laptop can have Wi-Fi, Ethernet, and a tether connected at once. A network tool needs to inspect the interface you selected, not whichever route the operating system prefers.

The tool needs to identify devices on a selected local network and combine host discovery, open ports, and advertised services into one readable result.

02 / ENGINEERING DECISIONS
01

Use the network that was requested.

The code binds mDNS to the chosen interface and TCP connections to its source address. That prevents a scan on one interface from quietly using another route.

02

Bound the parallel work.

Async TCP checks share a semaphore capped at 50 concurrent connections. Port scans and mDNS discovery run in parallel, while blocking service discovery runs through asyncio.to_thread.

03

Handle real machine constraints.

ARP discovery uses Scapy. When the platform or permissions prevent it from working, the tool can fall back to ICMP. Results merge by IP address and export as a Rich table or JSON.

04

Be clear about its limits.

This is an IPv4 local-network tool. It does not claim IPv6 discovery, vendor fingerprinting, or comprehensive retries. The README documents Windows and Linux use, the problems encountered, and where AI review helped.

THE TAKEAWAY

A correct tool needs careful boundaries: which interface, how much concurrency, and what happens when a dependency is unavailable.

Designed for networks the operator owns or is authorized to inspect. This portfolio does not run network scans.
